## Rozhodnutí během sprintu

- **Editor v TypeScriptu bundlovaný esbuildem** (bez tsc) – jediný výstup `wwwroot/cruma-editor.js`, sestavuje se
  v MSBuild před buildem `Cruma.Ui.Editor` (`npm ci`, když chybí `node_modules`). Výstup se necommituje.
  Build tedy vyžaduje Node.js (lokálně i v CI).
- **Rozšíření identifikátorů bloků** (CNT-002): `keepOnSplit: false` + `appendTransaction`, který podle mapování
  transakcí pozná původní blok – duplicitní id si ponechá posunutý originál, blok bez id na místě původního
  (změna typu, zabalení do seznamu) převezme jeho id, vnořené uzly id nenesou, vložený obsah přichází bez id.
- **Neznámé bloky a konflikty v editoru** jako neměnný uzel `crumaPreserved` s původním JSON – při uložení se vrátí
  přesně (CNT-005). Blok s neznámou značkou se také zachová celý.
- **Odkazy**: TipTap `isAllowedUri` + filtr při načtení JSON (nebezpečný odkaz ze serveru se nenačte) + kontrola
  `LinkPolicy` v C# před příkazem.
- **Motiv bez JS**: atribut `data-theme` na kořenovém prvku layoutu; tokeny `--cruma-*` pro oba režimy.
- **Web neumí režimy šířky editoru** (schopnost `EditorWidthModes` = false, ui-pattern §2), detail je responzivní;
  desktop je zapne v E-5.
- **Připojení = prohlížeč online a server dostupný** – síťová chyba volání API přepne klienta na offline, fronta se
  zkouší při změně sítě i každých 15 s.
- **Služby webového shellu jako singletony** – ve WebAssembly mají komponenty vlastní scope a připojení i fronta se
  spouštějí z kořene.
- **Webový klient posílá `X-Cruma-Client-Instance`** (jedno otevření aplikace) – bez něj server nespojoval uložení
  do verzí (N-3).
- **Ukládání v detailu jen jedno naráz**; když server výsledek sloučí a uživatel mezitím psal, lokální úpravy se
  převedou na sloučenou verzi tříbodovým merge ze `Cruma.Versioning` (jen pro zobrazení; autoritativní merge dál
  dělá server – VER-002).
- **Ruční úprava konfliktu** nahradí konfliktní blok odstavcem s textem a stejným identifikátorem bloku.
- **Testy API klienta** v `Cruma.Server.Tests` (skutečný server v procesu) – šablona nemá projekt testů klienta.

## Poznámky

- **Chyby nalezené až v prohlížeči** (testy je nezachytily, všechny opraveny):
  1. Seznam poznámek se nenačetl – výchozí tuple klíče `(Active, null, null, 0)` se rovnal výchozí hodnotě pole.
  2. Dvě rychlé změny spustily dvě souběžná ukládání ze stejné verze; druhé se sloučilo a editor se přepsal verzí
     bez posledního psaní – **ztráta textu**. Opraveno serializací ukládání a převodem lokálních úprav.
  3. Přechod z jedné poznámky na jinou nechal zobrazenou starou – data se načítala jen v `OnInitializedAsync`.
- NUnit používá jednu instanci fixture pro všechny testy – bUnit testy potřebují `InstancePerTestCase`, jinak se
  mocky sdílejí.
- Panel prohlížeče někdy nekreslí (okno vzadu) – interakce přes `javascript_tool` (`execCommand('insertText')`
  funguje s ProseMirrorem, `Blazor.navigateTo`).
- npm 11 hlásí `allow-scripts` u esbuild postinstall – nevadí, binárka přichází jako volitelná závislost platformy.
- První dotaz po startu serveru trvá ~9 s (sestavení modelu EF Core + připojení); pak desítky ms.
